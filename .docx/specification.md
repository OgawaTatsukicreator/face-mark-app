# 顔マスク処理アプリケーション 要件定義書

改訂日：2026/11/06

本書は追加機能の受入条件を定める。2026/09/11版の単画像仕様と一括処理計画を本版で置き換える。実装済み・検証済みという意味ではない。実装結果、実行したテスト、未確認事項は別途検証記録に残す。詳細設計は `docs/design.md` を参照する。

## 1. 目的と構成

利用者が写真の顔を隠し、隠す範囲を確認・修正して画像を保存できるWebアプリとする。PCとスマートフォンのブラウザを対象にする。

既存のNext.js 16／React 19のApp Router構成を継続する。ブラウザは入力、編集、Canvas描画と書き出しを担当し、サーバーの `POST /api/detect` は外部顔検知APIを中継する。APIキーはサーバー環境変数だけに置く。顔の自動検出には外部送信が必要だが、手動編集とサンプル利用には外部送信を必要としない。

今回の対象は26機能とする。元の依頼で一項目だった手動範囲の追加と削除をM06・M07に分け、入力5、検出／マスク8、出力／共有5、UI／UX8に対応させる。

## 2. 共通条件

| 項目 | 条件 |
|---|---|
| 入力形式 | JPEG、PNG、WebP。MIMEタイプと画像デコードを確認する |
| ファイルサイズ | 1枚10 MiB以下。0バイトや破損画像を受け入れない |
| 画像寸法 | 幅・高さとも8192 px以下、総画素数24,000,000以下 |
| 画像数 | セッション内で最大10枚。追加時に超過分を説明し、既存画像を上書きしない |
| 編集座標 | 元画像のピクセル座標。拡大表示の倍率で検出座標や出力解像度を変更しない |
| バッチ | 検出は一枚ずつ順番に実行。ある画像の失敗が後続画像の処理を止めない |
| タイムアウト | サーバーの外部API待機は10秒、ブラウザの一画像の通信待機は15秒 |
| 中断 | 利用者は一括検出を中断できる。完了済みの結果を保持し、未処理画像を編集可能な状態に戻す |
| 履歴 | 画像ごとにUndo用スナップショットを最大50件保持する |
| 初期マスク | 不透明な黒塗りを安全側の初期値とする |

有効な画像と不正な画像を一緒に選んだ場合、有効な画像を取り込み、不正な画像と件数を案内する。入力や送信の途中で現在の編集が破棄される場合は、操作の結果を明確にする。ファイルを選ぶだけでは外部APIへ送信しない。

## 3. 入力機能

| ID | 要件 | 受入条件 |
|---|---|---|
| I01 | ファイル選択ボタン | 画像を選ぶボタンを表示する。D&Dと共通の検証を通し、キーボードでも選択を開始できる。選択取消で既存画像を失わず、同じファイルを再選択できる |
| I02 | クリップボードから貼り付け | Ctrl／Cmd+Vで画像を取り込める。テキスト欄への通常の貼り付けを妨げない。対応ブラウザでは明示的な貼り付け操作も用意し、画像なし・権限拒否・API非対応を説明する |
| I03 | カメラ撮影 | カメラを開く明示操作後にだけ権限を要求する。ライブプレビューから撮影し、共通の画像入力へ渡す。拒否・機器なし・安全な接続でない場合に代替入力を案内する。取消・画面終了・アンマウントでカメラを停止する |
| I04 | 複数画像の一括入力 | 一度に複数ファイルを選択／ドロップし、セッション内最大10枚まで保持できる。一括検出を順次実行し、画像別の待機・処理中・成功・失敗と完了件数を表示する。1枚失敗しても他を処理する |
| I05 | サンプル画像 | 試す操作で、アプリが図形から作るサンプル画像と説明済みのデモ範囲を読み込む。人物写真や外部素材を必要とせず、外部API未設定でも編集と出力を試せる。サンプルでは自動検出を実行していないと表示する |

## 4. 顔検出とマスク機能

| ID | 要件 | 受入条件 |
|---|---|---|
| M01 | 複数人の検出と人数表示 | APIが返した有効な顔を全件保持する。検出数と、ON／OFF・閾値を反映した適用数を分けて表示する。元画像に一致する位置へ各マスクを描く |
| M02 | マスク種類 | 黒塗り等の単色、モザイク、ぼかし、スタンプを選択できる。スタンプはCanvasで描く自作の図形とし、絵文字フォントや外部画像への依存を避ける |
| M03 | マスク調整 | 色、透明度、モザイクの粗さ、ぼかしの強さ、サイズと位置を変更できる。選択顔への個別設定を持ち、画像全体の既定値と区別する。数値を許容範囲に制限し、画像外の描画を切り詰める |
| M04 | 顔ごとのON／OFF | 検出・手動追加した各範囲の適用を切り替えられる。OFFでも範囲情報を保持し、再ONで同じ位置・設定へ戻る |
| M05 | 検出枠のプレビュー | 顔と判定した範囲を重ねて確認できる。枠を表示／非表示にでき、選択範囲を見分けられる。枠、ハンドル、選択表示を保存画像に含めない |
| M06 | 手動範囲追加 | 画像上のドラッグまたはタッチで矩形を追加できる。顔なし画像とAPI失敗画像でも利用できる。ズーム・パン中も画像座標に一致し、画像外や面積ゼロの範囲を登録しない |
| M07 | 範囲削除 | 選択した自動／手動範囲を削除できる。別の顔を変更せず、Undoで設定を含めて復元できる |
| M08 | 信頼度による絞り込み | 0〜1の閾値を変更すると、APIを呼び直さず適用対象を更新する。信頼度は原則 `box.probability` から取得する。欠落値を勝手に100%にせず不明として表示し、不明な顔と手動範囲は閾値にかかわらず対象に含める |

低い透明度、弱いぼかし、細かいモザイク、範囲縮小、OFF、閾値の変更によって顔が見える場合があると案内する。自動検出は見落としや誤検出を起こし得る。アプリは匿名化の完全性を保証せず、保存前に利用者が全体と拡大表示を確認できるようにする。

## 5. 出力と共有機能

| ID | 要件 | 受入条件 |
|---|---|---|
| O01 | ダウンロード | ファイル名、PNG／JPEG、JPEGの画質を指定して現在の編集結果を保存できる。拡張子を形式に合わせ、危険なパス文字や制御文字を除去する。元の解像度で描き直したCanvasを出力し、JPEGの透明部分は白で合成する |
| O02 | クリップボードへコピー | 明示的な操作でマスク済みPNGをコピーする。対応状況、安全な接続、ブラウザ権限に応じた結果を表示し、失敗時はダウンロードを案内する |
| O03 | ビフォーアフター比較 | スライダーで元画像とマスク済み画像を重ねて比較できる。比較位置や元画像側の表示が出力画像を変えない |
| O04 | セッション内の処理履歴 | 一覧から以前読み込んだ画像を選び、画像ごとの検出結果と編集状態を呼び出せる。再選択だけでAPIへ再送信しない。削除・全消去で画像データを解放する |
| O05 | Undo／Redo | 種類・設定・ON／OFF・範囲追加／削除を画像単位で戻す／やり直す。Undo後に新しく編集した場合はその画像のRedoを消去する。画像切替、ズーム、比較位置は編集履歴に入れない |

出力は画像ピクセルから再生成し、元画像のEXIF等のメタデータを引き継がない。アプリが付加した位置情報や人物識別情報を含めない。使用ブラウザが画像エンコード時に作る技術的な情報まで除去したと断定しない。

## 6. UIと使い勝手

| ID | 要件 | 受入条件 |
|---|---|---|
| U01 | ダークモード | OS追従・ライト・ダークを選べる。OS追従中はシステムの変更へ追従し、文字と操作部を両テーマで確認する |
| U02 | レスポンシブ | PCとスマホの幅に応じて画像、一覧、編集部を配置する。狭い画面でページ全体の横スクロールを避け、ラベルや主要操作を切り詰めない |
| U03 | 日英対応 | 日本語／英語を切り替えられる。画面文言、操作ラベル、エラー、進捗と読み上げ用ラベルを翻訳し、文書の言語属性を合わせる |
| U04 | 処理状態 | 入力の読込中、検出中、完了数、中断とエラーを表示する。開始直後に状態を更新し、同時に二つの一括処理が始まらない。進捗は読み上げでも理解できる |
| U05 | 顔なしの案内 | 顔が見つからなかった結果を通信エラーとして扱わない。元画像を表示し、手動範囲追加または別画像選択へ進める |
| U06 | ズームとパン | 拡大・縮小、パン、表示リセットができる。画像外まで迷わず戻れ、拡大によって出力や編集範囲を変えない |
| U07 | 使い方とプライバシー説明 | 初回に入力→検出／手動編集→確認→保存の説明を表示し、後から開き直せる。外部送信の時点、保存範囲、カメラ／Clipboardの制約、自動検出の限界を説明する |
| U08 | 設定の記憶 | 言語、テーマ、よく使うマスク設定、ガイド既読を次回復元する。画像、ファイル名、検出座標、編集履歴、APIキーをlocalStorageへ保存しない。保存禁止や不正な保存値でも初期値で利用できる |

## 7. 非機能要件

### 7.1 応答と資源管理

入力検証と処理開始のフィードバックを、ネットワーク応答を待たず表示する。長い処理には現在の画像と完了数を表示する。画素数、画像数、履歴件数を制限し、Object URL、画像参照、Canvas、カメラのリソースを削除時と終了時に解放する。

### 7.2 操作性とアクセシビリティ

ファイル選択、検出、種類選択、顔選択、ON／OFF、削除、Undo／Redo、出力はキーボードで操作できる。各入力にラベルを付ける。状態を色だけで伝えず、フォーカスを確認できるようにする。矩形の手動追加はポインター操作に加えて数値による調整手段を用意する。実行していない支援技術の試験について適合を断定しない。

以下を具体的な設計判断に用いる。

- [SHIG #54 フールプルーフよりフェールセーフ](https://www.sociomedia.co.jp/9530)：編集・範囲削除をUndoで回復できるようにする。
- [SHIG #55 エラー表示は建設的にする](https://www.sociomedia.co.jp/9535)：失敗した画像と理由を説明し、再試行・手動編集・別入力を案内する。
- [SHIG #65 ユーザーの操作に対して0.1秒以内に反応を返す](https://www.sociomedia.co.jp/9715)：検出開始時に即座に処理状態を表示し、バッチの完了数を更新する。0.1秒という時間の達成は実測が必要であり、本書では未検証とする。
- [SHIG #82 モバイルでは包括的より階層的に](https://www.sociomedia.co.jp/9801)：狭い画面では画像選択、編集、出力をまとまりごとに配置し、高度な設定を必要時に開く。

### 7.3 対応環境

Windowsの現行Chromium系ブラウザを主要な自動確認対象とし、スマホ幅でも確認する。カメラとClipboard APIはブラウザ、権限、安全な接続、利用者の操作条件に依存する。非対応の環境では理由とファイル選択／ダウンロードの代替を表示する。実スマートフォン、実カメラ、OS間Clipboardは実機確認の結果を別記する。

## 8. プライバシーとセキュリティ

1. 利用者が外部送信を伴う検出ボタンを押す前に、写真をアプリのサーバー経由で外部顔検知サービスへ送ると説明する。入力、閲覧、手動編集、サンプル、出力では送らない。
2. アプリは画像や編集履歴をサーバーのファイル／データベース、ブラウザの永続ストレージへ保存しない。開いているページのメモリだけで管理し、更新や終了で失う。外部API側の保存期間や利用条件は運用者が確認し、アプリ内の保持方針と区別して説明する。
3. `FACE_API_URL` と `FACE_API_KEY` はサーバー環境変数で管理する。`.env` 系はGit対象外とし、公開する `.env.example` には実値を入れない。キーをクライアント、ログ、エラー本文、テスト成果物へ含めない。
4. APIはサイズ、MIME、画像の先頭シグネチャ、外部応答の型と座標を検証する。通信の失敗、タイムアウト、不正JSON、プロバイダーの拒否を区別し、安定したエラーコードを返す。外部APIのエラー本文、接続URLやキーをそのまま返さない。
5. API応答に `Cache-Control: no-store` を付ける。画像／座標／ファイル名／キーのログ記録を避ける。クライアントが任意の送信先URLやAPIキーを指定できるAPIを作らない。
6. カメラは明示操作時に開始し、取消・撮影終了・ページ終了時に停止する。Clipboardの読取／書込も明示操作だけで行い、内容を監視しない。
7. プレビューで原画像を確認できること、OFFや閾値等で一部の顔が出力に残り得ることを説明する。保存する前に利用者が顔の隠れ方を確認する。

## 9. 受入確認と変更管理

26個のIDに対するテスト対応表を作る。純粋なデータ処理、座標と履歴、APIの正常系／異常系を自動試験し、ブラウザで入力から編集・書き出しまで確認する。権限拒否、非対応、混在バッチ、一括処理中断、顔なし、壊れた画像、設定保存失敗を含める。

要件定義を独立コミットしてpushし、その後、設計を独立コミットしてpushする。実装は機能や依存関係に沿った小さいコミットに分け、対象の試験結果とともにpushする。未コミットの他者変更を上書きせず、force pushをしない。最終報告にはコミット、push状況、実施した確認と未完了事項を記載する。
