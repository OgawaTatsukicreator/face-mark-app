# 顔マスク処理アプリケーション 追加機能設計書

改訂日：2026/11/06

本書は `.docx/specification.md` の26機能を実装するための設計である。旧仕様書の画面・一括処理・データ構造に関する設計を置き換える。記載した確認はテスト方針であり、実行済みの証明ではない。実際の結果と実機で未確認の条件は検証記録に残す。

## 1. 既存構成と変更範囲

Next.js 16のApp Router、React 19、TypeScript、Tailwind CSS、Canvasを継続する。画像処理を外部サービスへ新たに移管せず、既存の `/api/detect` を顔検知の中継として使う。UIを組み立てるクライアントコンポーネント、入力／描画／編集履歴／翻訳等の補助モジュール、API Routeに分ける。グローバルな状態管理ライブラリや永続画像ストアは追加しない。

API側の画像検証には `sharp` を明示的な依存として使う。ブラウザ側は画像をデコードし、向きを反映したCanvasから標準化済みファイルを作る。この同じファイルをプレビューとAPI送信へ使い、EXIFの回転と検出座標の食い違いを避ける。

| 層 | 役割 |
|---|---|
| ページ／画面部品 | 入力、一覧、選択画像、検出操作、編集、出力、設定、ガイド |
| 入力処理 | 形式／容量／寸法検証、向きの反映、Canvas再生成、Object URLの作成と解放 |
| 編集モデル | 顔の集合、画像の既定設定、顔別設定、信頼度、Undo／Redo |
| 描画処理 | 元画像からマスクを再描画。編集用の枠と比較用の表示は別レイヤー |
| API Route | リクエスト検証、sharp検証、外部API送信、応答の型検証、エラーコード化 |

## 2. 画面と遷移

入力・編集・出力を一つの作業画面で扱い、セッション一覧から対象画像を選ぶ。初期状態と画像読込後で主要領域を切り替える。カメラとガイドは開閉できる独立領域とする。

| 現在の状態 | 操作 | 次の状態／扱い |
|---|---|---|
| 画像なし | ファイル選択、D&D、貼付 | 検証と標準化後に一覧へ追加し、追加画像を選択 |
| 画像なし／編集 | カメラを開く | 権限取得後ライブプレビュー。取消時は元の画面 |
| カメラ | 撮影 | PNG等のBlobを共通入力へ渡し、カメラ停止 |
| 任意 | サンプルを試す | 図形から作った画像とデモ範囲を追加。API送信なし |
| 画像選択済み | 顔検出 | 外部送信の説明を伴う明示操作から順次検出を開始 |
| 一括検出中 | 成功／失敗 | 対象画像の状態と完了数を更新し、次の画像へ |
| 一括検出中 | 中断 | 現在の通信をabortし、完了結果を保持。未処理は待機へ |
| 検出完了・顔なし／失敗 | 手動追加 | 元画像上で追加可能。API再試行も選択可能 |
| 編集 | 一覧の別画像を選択 | その画像の編集とUndo／Redoを復元。再送信なし |
| 編集 | 比較／ズーム／パン | 表示のみ変更。マスク設定や履歴を変えない |
| 編集 | 保存／コピー | 清潔な出力Canvasを生成し結果を近くに表示 |
| 任意 | 画像削除／全消去 | 対象のデータとURLを解放。最後の画像を消したら初期画面 |

狭い画面では画像一覧、選択画像、編集、出力の順に配置する。高度な設定を開閉できるようにし、主要な入力・検出・保存操作は見つけやすく保つ。根拠は [SHIG #82](https://www.sociomedia.co.jp/9801)。

## 3. 状態管理

画像には再利用しないIDを付け、配列位置で通信結果を紐付けない。画像切替や削除後に古い非同期処理が別の画像へ結果を書き込むことを防ぐ。

| 状態 | 内容と寿命 |
|---|---|
| セッション画像 | 最大10件。標準化済みFile／Blob、Object URL、幅・高さ、検出状態、エラー、編集履歴。メモリのみ |
| 元検出範囲 | ID、元画像の矩形、`probability: number \| null`、自動検出／手動の由来 |
| 編集状態 | 顔の範囲、ON／OFF、画像の既定マスク、顔別の上書き、信頼度閾値 |
| 履歴 | 画像ごとのpast／present／future。過去最大50件。FileやCanvasの画素バッファを複製しない |
| 表示状態 | 選択画像／選択顔、ズーム、パン、操作モード、比較位置、枠表示、開いているパネル |
| バッチ | 実行ID、対象IDのスナップショット、現在ID、完了数、実行中フラグ、AbortController |
| 設定 | 言語、テーマ、マスクの既定値、ガイド既読。版付きでlocalStorageへ保存 |

顔別の上書きは種類、色、透明度、粗さ／ぼかし量、拡大率、位置とする。未指定の項目だけ画像の既定値を参照する。位置や大きさの変更後も、APIが返した元範囲を失わない。手動範囲の信頼度は `null` とする。

### 3.1 Undo／Redo

編集操作を純粋な状態変換として扱い、実際に内容が変わった場合だけ履歴へ追加する。新しい編集はfutureを消去する。Undoはpresentをfutureへ移し、past末尾をpresentにする。Redoは逆に行う。スライダー等の連続操作は可能なら一つの操作へまとめ、最大50件の上限を守る。

顔の種類・設定・ON／OFF・追加・削除・閾値変更を戻せるようにする。画像選択、ズーム、パン、比較、枠の表示切替を履歴へ入れない。検出を再実行して範囲を置き換える場合も、直前の編集状態を履歴から回復できるようにする。[SHIG #54](https://www.sociomedia.co.jp/9530)を範囲削除と設定試行の回復へ適用する。

## 4. 入力とデータフロー

1. ファイル選択、D&D、pasteイベント、Clipboard API、カメラ撮影、サンプルの各入口から、共通の入力処理へFile／Blobを渡す。
2. 画像数、MIME、0バイト、10 MiB上限を検査する。デコード後に各辺8192 px以下、24,000,000画素以下を確認する。
3. ブラウザのデコード時の向きを反映してCanvasへ描き、メタデータを引き継がない画像へ再生成する。標準化後も容量上限を確認する。プレビューと送信はこの同一画像を使う。
4. 有効な画像のURLを作り、メモリへ追加する。失敗した画像だけを理由付きで報告する。追加処理中は排他制御し、同時入力でも最大10枚を超えない。
5. 検出操作まで写真を送信しない。サンプルはアプリ内の図形から描き、デモ用範囲と共に登録する。
6. 検出を開始したら、対象IDのリストを固定して一枚ずつ `/api/detect` へ送る。結果はIDと実行IDを照合して反映する。

入力検証中にURLを作った後で失敗した場合もURLを解放する。画像削除・全消去・アンマウント時に全URLを解放し、進行中の通信を中断する。非同期の画像デコードやCanvas生成が終了しても、破棄済みの画面へ状態を書き戻さない。

### 4.1 カメラとClipboard

`getUserMedia` はカメラを開く操作からだけ呼ぶ。返されたMediaStreamを保持し、撮影・取消・終了で全trackをstopする。権限取得の待機中に領域を閉じた場合、遅れて返ったstreamも停止する。

pasteイベントでは画像の項目だけを取り込み、input／textarea等のテキスト編集を妨げない。`navigator.clipboard.read`／`write` は明示操作から呼ぶ。利用可能なAPIと安全な接続を確認し、権限拒否を捕捉する。読み込みができなくてもファイル選択、書き込みができなくてもダウンロードへ進める。

## 5. API契約とエラー

### 5.1 `POST /api/detect`

入力は既存と同じ `multipart/form-data` の `file` 一件。接続先とキーは `FACE_API_URL`／`FACE_API_KEY` から取得し、クライアントの指定を受け付けない。サーバーはmultipart、容量、MIME、画像シグネチャを確認し、sharpによるメタデータ取得／デコード検証で寸法と画素数の制約を適用する。異常な画像は外部APIへ送らない。

外部送信時は正しいMIMEとファイル名を使い、APIキーを `x-api-key` に設定する。10秒のタイムアウトとリクエスト中断を適用する。すべての応答を `Cache-Control: no-store` とする。

成功時は既存の `result` 配列を保ち、各要素に `box` を含める。座標は `x_min`、`y_min`、`x_max`、`y_max` の元画像ピクセル値。信頼度は `box.probability` に0〜1の有限数または `null` を入れる。上流で信頼度が欠落したときは `null` に正規化する。空の `result` は正常な顔なし結果である。

応答全体、配列件数、各boxの型、有限数、座標の順序、元画像への収まり、確率の範囲を検証する。小さい丸め誤差を切り詰める場合も、不正な長さや空の矩形を有効な顔へ変えない。不正応答を部分的に成功へ見せかけない。外部APIの追加フィールドやエラー本文は転送しない。

### 5.2 エラー処理

APIは翻訳済みの長文や内部例外を返さず、安定した文字列のエラーコードを返す。クライアント側でコードを日本語／英語と次の操作へ対応付ける。具体的なコード名は実装とテストで一元管理する。

| HTTP | 原因 | 画面上の扱い |
|---|---|---|
| 400 | multipart不正、ファイルなし／空、画像内容の不正 | 別の画像を選ぶ。既存画像の編集を保持 |
| 413 | 容量・寸法・画素数の上限超過 | 上限を説明して小さな画像を案内 |
| 415 | 対応形式外、宣言MIMEとシグネチャの不一致 | JPEG／PNG／WebPを案内 |
| 500 | サーバー設定不足または内部処理失敗 | 接続設定の確認を案内し、写真・キー・URLを表示しない |
| 502 | 外部API拒否、不正JSON、不正な検出結果、接続失敗 | 対象画像の失敗として再試行／手動編集を案内 |
| 504 | 外部APIの10秒タイムアウト | 後での再試行／手動編集を案内 |
| クライアント内 | 15秒タイムアウト、通信切断、利用者の中断 | 原因を区別。中断は失敗の警告として扱わない |
| 200＋空配列 | 顔なし | 画像を残して手動追加／別画像を案内 |

予期しないクライアント側のエラーも画像単位で捕捉し、バッチを続ける。開始フラグはstate反映前の連打も防ぎ、終了処理で必ず解除する。開始直後の処理状態と完了数の更新は [SHIG #65](https://www.sociomedia.co.jp/9715)、次の行動を示す文言は [SHIG #55](https://www.sociomedia.co.jp/9535)による。

## 6. マスク描画

毎回、標準化済みの元画像から出力用Canvasを描き直す。前回マスク済みのCanvasへ追加描画し続けない。ONかつ、信頼度が不明／手動、または閾値以上の範囲だけを描く。OFFや閾値で除外された顔は元データを保持する。

矩形の中心へ位置差分を加え、幅・高さに拡大率を掛けて描画範囲を求める。浮動小数の境界は外側へ丸め、画像との共通領域でclipする。範囲外、面積ゼロ、不正数の状態を保存させない。

| 種類 | 処理 |
|---|---|
| 単色 | clip範囲を選択色と透明度で塗りつぶす |
| モザイク | 元画像の対象領域を粗さに応じた小さい作業Canvasへ縮小し、平滑化を無効にして拡大。元画像へ指定透明度で重ねる |
| ぼかし | 対象周囲に余白を取った元画像からぼかし用Canvasを作る。clip内へ描き、端の透明な縁を避ける。未対応時は安全に扱える方式か案内を用意する |
| スタンプ | 外部素材を使わず、自作の塗りつぶした顔図形等を矩形全体を覆う下地の上へ描く |

作業Canvasを顔数分ずっと保持しない。重なった範囲も元画像から効果を生成し、処理の積み重ねによる画質の変化を抑える。

### 6.1 編集座標と表示

編集用Canvasの上に枠や選択状態を重ねる。Pointer Eventsでドラッグの開始点／現在点を取り、表示領域の矩形と画像の実寸比率から元画像座標へ変換する。パンやCSS拡大を含めた位置へ対応させる。pointer capture、取消、上下逆のドラッグを扱う。追加とパンの操作モードを分け、タッチスクロールと競合させない。数値入力でも範囲を調整できる。

比較は元画像とマスク済み描画を同じサイズで重ね、比較位置に応じて表示を切り分ける。ズーム・パン・比較・枠は表示層の状態に留める。

## 7. 出力

出力時は元の幅・高さを持つ別Canvasに編集済みピクセルだけを描く。検出枠、選択枠、比較用の元画像表示、ズーム・パンを含めない。PNGまたはJPEGのBlobを作り、JPEGでは初めに白で背景を塗る。画質指定をJPEGエンコーダーへ渡す。

ファイル名のパス区切り、制御文字、Windowsで使えない文字を除去し、空なら既定名を使い、拡張子を形式に合わせる。ダウンロード用Object URLはクリック処理の完了後に解放する。コピー時は `ClipboardItem` でPNGのBlobを書き込み、成功／失敗を表示する。Canvas再生成により元画像のEXIF等は引き継がない。

## 8. 設定とプライバシー

設定は版、言語、テーマ、検証済みのマスク既定値、ガイド既読だけを保存する。読取・JSON解析・書込を例外処理し、型と範囲が不正な値は既定値に戻す。`system` テーマはOS変更へ追従する。言語変更時は表示文言と `html.lang` を合わせる。

画像、ファイル名、座標、Undo／Redo、APIキーを永続化しない。アプリ側は画像を保存しないが、自動検出で外部サービスへ送ること、そのサービスの保持期間をアプリが保証できないことを案内する。生画像・キー・上流本文をログへ出さない。サンプルは完全にローカルで動作する。

## 9. テスト方針

| 対象 | 主な確認 |
|---|---|
| 入力 I01〜I05 | 選択／D&D／pasteの共通検証、混在入力、10枚制限、0バイト、容量・寸法・画素数境界、破損、回転画像の一致、サンプルの外部通信なし |
| API | ファイルなし、偽MIME、過大寸法、設定不足、上流正常／空／不正JSON／拒否／タイムアウト、不正box／probability、no-store、キーと上流本文の非露出 |
| マスク M01〜M08 | 複数顔、信頼度不明、閾値境界、ON／OFF、範囲追加／削除、座標変換、重なり、全種類と透明度・色・粗さ・位置 |
| 履歴 O04〜O05 | 画像間独立、Undo／Redo、新規編集でRedo消去、50件上限、再検出後の回復、再選択による再送信なし |
| 出力 O01〜O03 | 元解像度、PNG／JPEG、JPEG白背景、画質、名前、出力Blob、マスク画素、枠・比較・ズームの混入なし、コピー成功／拒否／非対応 |
| UI U01〜U08 | 日英、OS追従と手動テーマ、設定復元／破損／保存拒否、ガイド再表示、顔なし、スマホ幅、キーボード、フォーカスとラベル |
| バッチ／後始末 | 順次実行、一部失敗、中断、連打、削除や終了後の遅い応答、Object URL解放、遅れて許可されたカメラの停止 |

座標・信頼度・設定・履歴は純粋関数の試験、APIは外部サービスを差し替える自動試験、Canvasと画面遷移はブラウザ試験で確認する。カメラは可能なら仮想入力で、Clipboardは対応APIのモックと許可／拒否を分けて確認する。実外部APIの疎通は別記し、自動モック試験だけで実サービスの検出品質を確認済みにしない。

Windowsのブラウザとスマホ幅で画面を確認し、必要なテスト・lint・型検査・本番ビルドを実行する。実スマートフォン、実カメラ、OS Clipboardの他アプリ連携、支援技術、実外部APIは、実行できた範囲と未確認を明記する。秘密情報を含まない結果と対応IDを検証記録へ残す。

## 10. 実装とコミット

要件定義、設計をそれぞれ独立コミット・pushしてから実装する。共通の画像／編集モデル、API検証、入力、検出／編集、出力、UI設定の依存関係に沿い、レビュー可能な小さい機能単位でコミットする。各段階で関連する確認を行い、まとめて完了扱いにしない。

変更前のGit状態とremote／branchを記録する。秘密情報と他者の未コミット変更を含めず、force pushを使わない。検証記録と最終報告にコミット一覧、push状況、残った問題を記載する。
